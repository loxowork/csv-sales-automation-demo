# CSV売上データの結合・検証・日別集計

自主制作デモです。顧客への納品実績ではありません。入力・出力に含まれる商品名と注文番号はすべて架空です。

複数のCSVを集計する前に、空欄や二重取り込みを確認する作業を想定しています。正常な行を結合し、確認が必要な行を別ファイルに分け、正常な行だけで日別売上を集計します。Python標準ライブラリのみで動作し、ファイルを外部に送信しません。

## 実行

Python 3.10以降を使用します。追加パッケージ、APIキー、有料サービスは不要です。リポジトリのフォルダーで実行してください。

```bash
python csv_sales.py sample/sales_01.csv sample/sales_02.csv --output-dir actual_output
python -m unittest discover -s tests -v
```

Windowsで`python`が見つからない場合は`py -3`に置き換えてください。入力はUTF-8（BOMの有無どちらも可）。CP932は`--encoding cp932`で指定します。

出力先は新しいフォルダー、または空のフォルダーを指定します。既存の結果を上書きしません。再実行には別の出力先を指定してください。

## 入力と出力

| 種類 | ファイル | 内容 |
| --- | --- | --- |
| 入力 | `sample/sales_01.csv`, `sample/sales_02.csv` | `order_id,date,item,quantity,unit_price`の順で5列 |
| 出力 | `clean.csv` | 検証を通った行と`amount`（数量×単価）。数量・単価を表記統一 |
| 出力 | `errors.csv` | 元ファイル名、CSVレコード番号、理由コード、対象行の値 |
| 出力 | `daily_summary.csv` | 正常行だけの日別数量・金額合計 |

`output/`は同梱サンプルの期待出力です。実行結果は`actual_output/`などに作成します。出力CSVはExcelで扱いやすいUTF-8 BOM付きです。

## 検証ルール

全5項目を必須とし、前後の空白を除いた後に空欄を確認します。ヘッダーの名前・順序が違う場合は処理を中止し、新しい出力は作りません。列数の不一致はエラー行として分離します。

注文番号と商品名の組を重複キーにします。ファイル名順・ファイル内の行順で、最初に検証を通った行を採用し、後の同じキーは`duplicate_order_item`として分離します。実際の業務で同じ注文に同じ商品が複数行ある場合は、このキーを変更する必要があります。

日付は`YYYY-MM-DD`の実在する日付、数量は1〜1,000,000の半角整数、単価は0〜1,000,000,000・小数第2位までです。金額計算にはDecimalを使用します。注文番号・商品名が`= + - @`で始まる行は分離し、エラーCSVの該当文字列には先頭にアポストロフィを加えます。これは表計算ソフトで数式として扱われるのを抑えるためで、元の文字列と完全一致する出力ではありません。

## サンプル実行結果

```text
accepted=5 rejected=5
```

入力10行のうち5行を採用し、5行を分離します。欠落した商品名、不正な日付、重複、不正な数量、負の単価を含む例です。正常行の売上合計は2,561.50です。

| 日付 | 数量 | 金額 |
| --- | ---: | ---: |
| 2026-10-01 | 3 | 1100.00 |
| 2026-10-02 | 7 | 1161.50 |
| 2026-10-03 | 1 | 300.00 |

テストは同梱期待出力とのバイト一致、日別合計、引用符・改行・カンマ、少数金額、エラー分離、CP932、数式形式の文字列、異常ヘッダー、既存出力の保護を確認します。

## 範囲と制限

このデモは指定5列のCSV専用です。Excelブック、PDF/OCR、会計・請求書の税計算、ECサイトへの送信、定期実行、GUIには対応していません。ファイルごとの文字コード自動判定はありません。結果をメモリーに保持するため、大容量データ向けの性能検証はしていません。

CSV構文や文字コードのエラーでは処理を中止します。ファイル書き込み中のディスク障害については、全出力の一括ロールバックは行いません。行番号は複数行フィールドを1件と数えるCSVレコード番号です。Windows実機での操作確認は未実施です。

実案件では匿名サンプルを確認し、列定義、重複キー、データ量、例外処理、納品・検収条件を合意してから対応範囲を決めます。会社・顧客のデータ、個人情報、認証情報はこの公開リポジトリに含めません。
